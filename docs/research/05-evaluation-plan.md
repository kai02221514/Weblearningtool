## 評価目的

評価は、正式な主RQに対するシステムレベル検証と、将来評価の副次RQに対する実参加者による利用評価を分離して扱う。

### 正式な主RQに対するシステムレベル検証

- [確定事項] 対象は、D-021で確定した正式な主RQである。
- [実装済み／技術検証済み] KAI-26 / PR #27で、`route-spec/1.0`準拠、MVP 12ノード限定、UI非依存の純粋で決定的な`routeGenerator`を実装した。代表シナリオ、自動テスト、PR段階CI、`main` push CIに成功している。
- [部分実装／技術検証済み] KAI-27 / PR #30で、診断K群3項目、ブラウザ内メモリの進捗、確定済み確認テスト結果をルート生成へ接続し、Dashboardの固定推薦を生成順の上位3件へ置換して`main`へ反映した。自動検証および認証・保存・外部通信を使わない専用ハーネスで確認した。
- [確認済み範囲] KAI-26 / PR #27とKAI-27 / PR #30の技術検証では、少なくとも次を確認した。
  - 同一入力スナップショットに対する出力の決定性。
  - 全出力ノードがMVP 12ノード集合内にあること。
  - 前提未完了ノードを直接推薦せず、前提関係を満たすこと。
  - 6段階優先順位が競合入力へ適用されること。
  - 証拠の新しさ、反復回数、カタログ定義順による同点処理が全順序を作ること。
  - `reasonCode`と`evidence`により推薦根拠を追跡できること。
  - `specVersion`、`catalogVersion`、`dataVersion`を出力すること。
  - 代表シナリオで、入力状態に応じたルート変化、前提補完、復習、新規学習の順序を確認できること。
- [後続実装・合成検証済み] KAI-28 / PR #34で診断K群3項目の保存・明示的再ログイン後復元、保存成功ゲート、失敗時再試行を実装した。KAI-29で通常entryのlocal合成導線、KAI-32〜34で通常運用の表示名保存と指定remoteでの診断・表示名API境界を検証した。KAI-36 / PR #52とPR #51の統合では、補助エラーによる復習を純粋生成器の契約に合わせ、PR #53で証跡をmainへ反映済みである。
- [未接続・未実装・未評価] 通常画面からの実践課題エラー履歴・振り返りのルート入力、表示名・診断以外の永続化、同意、評価ログ、研究データ出力、実参加者による利用評価は未完了である。上記のlocal通常導線・remote API合成検証を、参加者用の永続化や研究データ収集の完成へ一般化しない。
- [検証集合の区別] 最終予稿§4.3の24テストは当時の生成器を対象とする限定検証である。2026-10-01のmain `d3f2bf5` のCheckは全20ファイル248テストを含む別時点・別集合であり、予稿の数値を書き換えない。KAI-48では既存CI記録を照合し、アプリ検証をローカルでは再実行していない。文書PRで自動起動するCIは別の証跡としてPRに記録する。
- [制約] 型検査、自動テスト、ビルド、CIの成功はシステム実装契約と参照整合性の証拠であり、学習者に対する有効性、納得感、学習成果の証拠ではない。

### 将来評価の副次RQに対する利用評価

- [確定事項] 対象は、生成された学習ルートと推薦理由が、プログラミング初学者にとって次に学ぶ内容の明確さと提示内容への納得感を支援するかという副次RQである。
- [未評価] この副次RQは予備試行または本評価で扱う。現時点では肯定的な結論を出さない。
- [評価候補] 個別ルートが学習者にとって納得可能か、次学習内容が明確か、難易度が適切に感じられるかを確認する。
- [評価候補] エラー分類と復習提示が原因理解に役立つか、振り返りが理解状態の把握と次の行動計画に役立つか、学習継続意欲を支援する可能性があるかは副次的な観察候補とし、D-021で効果を確定済みとは扱わない。

## 取得できる場合に用いる補助指標

[暫定仕様] 以下はログ取得負荷と分析目的を確認した上で採用する。

- 完了ノード数
- テスト得点
- 実践課題達成状況
- エラー発生・解消履歴
- 再受験回数
- 推薦ノード選択率
- 振り返り記入率

- [研究者暫定判断・指導教員未確認] 初回評価では学習時間を補助指標に採用しない。イベント時刻は順序確認・監査に必要な範囲で保持し得るが、開始・終了時刻の差を学習時間として分析しない。予備試行後に測定方法と分析目的が明確になった場合は再検討する。

[注意] 小規模評価では統計的な優越性より、モデルが想定どおり機能するか、利用者が提示を理解・受容できるかを中心に扱う。
