## 評価目的

評価は、正式な主RQに対するシステムレベル検証と、将来評価の副次RQに対する実参加者による利用評価を分離して扱う。

### 正式な主RQに対するシステムレベル検証

- [確定事項] 対象は、D-021で確定した正式な主RQである。
- [実装済み／技術検証済み] KAI-26 / PR #27で、`route-spec/1.0`準拠、MVP 12ノード限定、UI非依存の純粋で決定的な`routeGenerator`を実装した。代表シナリオ、自動テスト、PR段階CI、`main` push CIに成功している。
- [部分実装／技術検証済み] KAI-27 / PR #30で、診断K群3項目、ブラウザ内メモリの進捗、確定済み確認テスト結果をルート生成へ接続し、Dashboardの固定推薦を生成順の上位3件へ置換して`main`へ反映した。自動検証および認証・保存・外部通信を使わない専用ハーネスで確認した。
- [確認済み範囲] KAI-26 / PR #27とKAI-27 / PR #30の技術検証では、少なくとも次を確認した。
  - 同一入力スナップショットに対する出力の決定性。
  - 全出力ノードがMVP 12ノード集合内にあること。
  - 前提未完了ノードを直接推薦せず、前提関係を満たすこと。
  - 6段階優先順位が競合入力へ適用されること。
  - 証拠の新しさ、反復回数、カタログ定義順による同点処理が全順序を作ること。
  - `reasonCode`と`evidence`により推薦根拠を追跡できること。
  - `specVersion`、`catalogVersion`、`dataVersion`を出力すること。
  - 代表シナリオで、入力状態に応じたルート変化、前提補完、復習、新規学習の順序を確認できること。
- [後続実装・合成検証済み] KAI-28 / PR #34で診断K群3項目の保存・明示的再ログイン後復元、保存成功ゲート、失敗時再試行を実装した。KAI-29で通常entryのlocal合成導線、KAI-32〜34で通常運用の表示名保存と指定remoteでの診断・表示名API境界を検証した。KAI-36 / PR #52とPR #51の統合では、補助エラーによる復習を純粋生成器の契約に合わせ、PR #53で証跡をmainへ反映済みである。
- [未接続・未実装・未評価] 通常画面からの実践課題エラー履歴・振り返りのルート入力、表示名・診断以外の永続化、同意、評価ログ、研究データ出力、実参加者による利用評価は未完了である。上記のlocal通常導線・remote API合成検証を、参加者用の永続化や研究データ収集の完成へ一般化しない。
- [検証集合の区別] 最終予稿§4.3の24テストは当時の生成器を対象とする限定検証である。2026-10-01のmain `d3f2bf5` のCheckは全20ファイル248テストを含む別時点・別集合であり、予稿の数値を書き換えない。KAI-48では既存CI記録を照合し、アプリ検証をローカルでは再実行していない。文書PRで自動起動するCIは別の証跡としてPRに記録する。
- [制約] 型検査、自動テスト、ビルド、CIの成功はシステム実装契約と参照整合性の証拠であり、学習者に対する有効性、納得感、学習成果の証拠ではない。

- [確定事項] 対象は、生成された学習ルートと推薦理由が、プログラミング初学者にとって次に学ぶ内容の明確さと提示内容への納得感を支援するかという副次RQである。
- [未評価] この副次RQは予備試行または本評価で扱う。現時点では肯定的な結論を出さない。
- [確定事項] D-028により、次学習内容の明確さと推薦理由・内容への納得感を中核とし、難易度、エラー説明・復習提示、振り返り、継続可能性の改善点を補助的に確認する。
- [制約] 学習効果、能力向上、固定ルートへの優越性、統計的優越性または一般化可能な効果量は扱わない。

### 予備試行の確定範囲

- [確定事項] D-025により、予備試行はMVP 12ノード全体を対象とする単群の実行可能性確認とする。
- [確定事項] 参加者は学生のみ3〜5名とし、HTML/CSS未経験者と初学者相当の経験者を含める。実務経験者および基本的なWebページを独力で設計・実装できる者は対象外とする。
- [確定事項] 確認対象は、同意から診断、教材、確認テスト、実践課題、振り返り、事後評価、研究データ出力、撤回・削除までの実施可能性、運用上の問題、推薦理由の理解、次学習内容の明確さ、負担および改善点である。
- [確定事項] 結果は記述的・質的に扱い、固定ルートとの比較、個別化の優越性、学習成果の改善、統計的優越性または長期効果を主張しない。

## 予備試行用評価票

- 評価票版: 実施版ごとに一意な版IDを付与し、具体値は実施版の確定時に記録する
- 実施時点: 12ノードの学習終了後、事後説明の前に1回
- 中核4項目: 回答必須
- 補助4項目: 回答必須。ただし「該当なし／体験していない」を許容
- 途中中止者: 同意が有効で本人が希望する場合だけ、中核4項目の短縮版を任意で提示

### 中核4項目

1. 提示された学習ルートを見て、次に何を学べばよいか分かった。
2. 各教材が推薦された理由を理解できた。
3. 自分の診断結果や学習状況に照らして、推薦内容に納得できた。
4. 提示された学習順序は、自分の学習状況に合っていると感じた。

### 補助4項目

5. 教材・確認テスト・実践課題の難易度は適切だった。
6. エラー説明や復習提示は、つまずきの理解に役立った。
7. 振り返りは、次に取り組む内容を考えるのに役立った。
8. この学習方法を継続して利用できそうだと感じた。

### 回答尺度

1. 全くそう思わない
2. あまりそう思わない
3. どちらともいえない
4. ややそう思う
5. 強くそう思う

Q6・Q7等の未体験機能に備え、数値尺度とは別に「該当なし／体験していない」を設ける。これは欠損と同一視せず、数値の有効回答から除外して人数を別に示す。

### 自由記述

- D-029により、初回予備試行の評価票から自由記述を除外する。入力欄を設けず、入力・送信・保存・分析を行わない。
- 将来の試行で自由記述を検討する場合は、目的、同意、保存、権限、保持、削除および分析を別Decisionで再確認する。音声、動画およびインタビュー録音は行わない。

## 分析計画

- 項目ごとに回答カテゴリ別人数、有効回答数、中央値、最小値〜最大値、「該当なし／体験していない」の人数を示す。
- 平均値、標準偏差、p値、信頼区間、効果量および推測統計を主結果として使用しない。
- 複数項目を合算した尺度得点を作らず、信頼性または尺度妥当性を主張しない。
- 欠損と「該当なし／体験していない」を分離し、欠損値を補完しない。
- 初回予備試行では自由記述を収集・分析せず、原文を掲載しない。
- 属性別の小セル分析を行わず、D-028の8項目について項目別の全体記述集計を基本とする。
- 原データと派生値を分け、対象commit、ルート仕様版、教材版、問題集合版、評価票版、計測版、派生定義および生成日時を追跡する。

## 中止・欠損・除外

- 完遂者と途中中止者を区別し、途中中止者の回答を完遂者と同一の結果として単純集計しない。
- 中止理由は「本人希望」「体調」「技術障害」「その他」に分類する。
- 撤回時はKAI-12で確定する手順に従う。
- 除外は、対象条件不適合、同意未取得、参加撤回、評価データが成立しない技術障害、訂正不能な破損・重複に限定する。
- 低い評価または否定的意見を除外理由にせず、除外数と理由を報告する。

## 予備試行後の修正要否の目安

- 中核項目で1または2が1件でもあれば理由を確認する。
- 同じ中核項目で2名以上が1または2なら、予備試行後の修正対象とする。
- 「該当なし／体験していない」が想定外に多い場合は、機能到達性または手順を確認する。
- Critical／High相当の技術・安全性問題があれば試行を停止する。
- この目安だけで副次RQを肯定または否定しない。

### 募集開始のGo/No-Go（D-031）

- 学生3〜5名を対象とし、HTML/CSS実務経験者を除外する。成績、授業評価および指導関係から切り離した中立的な任意募集とし、募集連絡先を研究データから分離する。
- 対象・人数・募集方法、説明同意、連絡先管理、強制手続および保存削除説明が揃った場合だけ、研究者本人がGoとする。未達はNo-Goとする。

### 所要時間・休憩（D-031）

- KAI-46の正常完遂時間へ20%程度の余裕を加えて案内時間を決める。
- 30分ごとに5分以上の休憩を設け、任意休憩・中止を認める。
- 12ノード完遂が過大負担と判明した場合は、範囲を暗黙に縮小せずD-025を明示的に再判断する。

### 予備試行開始のGo/No-Go（D-031）

- 12node分の教材・3問クイズ・実践課題、KAI-41の詳細契約、参加者環境、同意・研究log・固定版export・撤回削除、KAI-46の合成通し検証、実施版固定およびCritical/High 0件を確認した場合だけ研究者本人がGoとする。
- CI成功だけではGoとしない。未達はNo-Goであり、文書作成、Issue登録またはblock解除を開始許可とみなさない。

### 予備試行後と本評価（D-031）

- 予備データを本評価データへ混合しない。D-028の修正目安に従い、実質変更時は版を更新し、必要なら再予備試行する。
- 本評価へ進む場合は対象数、比較条件および分析方法を新Decisionで確定する。資源不足の場合は研究上の主張を実行可能性評価までに限定する。
